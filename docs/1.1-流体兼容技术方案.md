# 1.1 流体兼容技术方案

状态：代码已实现，待游戏内验收
目标版本：1.1.0
适用版本：Minecraft 1.20.1 / Forge 47.x

## 目标

将 ProjectE 个人 EMC 空间中的流体接入 AE2 与 Refined Storage：玩家可在对应终端查看流体、提取流体，并让网络中的流体设备按各自存储 API 使用流体。ProjectE 仍是 EMC 与 Knowledge 的规则来源；AE2、RS 只负责呈现和传输。

本次目标是可在游戏内验收的流体闭环，并继续保持 AE2、RS 为独立软依赖。只安装其中一个时，另一个平台的类和注册逻辑不能被加载。

## 参考实现考察

[Project Expansion: Arcanum 的 EMC Link](https://github.com/WJXhhh/Project-Expansion-Arcanum/blob/1.20.1-arcanum/src/main/java/com/wjx/forge/projectexa/block/entity/BlockEntityEMCLink.java) 将 Forge `IFluidHandler` 暴露为只读的虚拟流体槽。配置的输出物品是装有流体的桶；接口根据该桶取得流体类型，排出时检查所有者、流体类型、剩余输出额度和 EMC 余额，并只在实际执行时扣 EMC。它还按每毫升的 EMC 成本计算可排出量。该实现通过额度控制输出，不维护已取出一整桶后待分次排出的实体流体缓存。

因此，参考代码可以借鉴流体识别、模拟/执行分离、按实际排出量计费等规则；本项目需要增加的整桶缓存是为适配“ProjectE 侧只能按 1B 取出、终端/API 可以按 1mB 请求”的约束而设计的额外层。

## 建议的首版范围

- 只开放能由已注册桶物品表示、且 ProjectE 为其提供正 EMC 值的流体。
- 流体键由 Forge 流体注册表 ID 和流体标签组成；同一流体的不同标签不合并。
- 玩家必须在 ProjectE Knowledge 中学会对应的装液桶物品后，该流体才进入其终端目录。接口学习到桶物品后沿用 1.0 的知识更新路径。
- 每个桶对应 1000mB。首版不支持没有桶表示的流体，也不模拟流体容器物品本身。
- 终端中的数量使用 mB。转移流体不生成或消耗空桶物品；提取液体只改变 EMC 账户和本模组的流体缓存。
- NBT 开关仍只决定带 NBT 的物品是否可输入。流体缓存键保留 FluidStack 标签，禁止不同标签的流体混入同一缓存。

若后续需要支持非桶装流体，应添加明确的流体到 ProjectE 定价规则，而不是猜测其 EMC 价格。

## EMC 定价

建议每 1000mB 的价格等于对应装液桶的 ProjectE EMC 值，单位成本为：

```text
emcPerMb = filledBucketEmc / 1000
```

公式用于显示容量和成本换算，内部保留有理数精度。受 ProjectE 按整桶提取的约束，只有余额足以支付一个装液桶的完整 EMC 值时，才能从 EMC 兑换一批 1000mB；少于一桶 EMC 时不产生部分桶。每次兑换整批时扣除该桶的完整 EMC 值，流体进入缓存后即可按 1mB 分批排出。这样多次小请求的累计费用仍恰好等于已兑换整桶的价值，不会因每次 `drain` 的取整而变化。

Arcanum 还提供了按空桶 EMC 和物质等级效率折算的成本公式。当前桥接没有对应的等级系统，建议 1.1 首版不引入等级折扣，先以装液桶完整 EMC 值定价。是否要提供全局空桶抵扣配置，留待确认。

## 整桶缓存与交易

新增平台无关的 Fluid Core，负责目录、EMC 换算、缓存和事务。缓存以“玩家 UUID + 流体 ID + FluidStack 标签”为键，在 AE2 与 RS 共用，避免同一玩家通过两个网络重复获得一份流体。

建议把缓存作为已预付的流体库存：

1. 浏览或模拟请求只计算“现有缓存 + 每个可完整支付的装液桶对应的 1000mB”，不扣 EMC，也不创建缓存。
2. 执行提取时优先使用缓存余额；缓存不足 1000mB 时，只有账户能支付完整一桶 EMC 才从 ProjectE 兑换一批 1000mB 并加入缓存。余额不足一桶时，不兑换部分流体。
3. 将本次请求量从缓存中扣除，未用完的毫升数仍作为可见的已付费库存。
4. 若同一请求需要多于一桶，则循环按桶补充，直到满足请求或账户余额不足。余额不足时，返回已经能满足的部分数量。
5. 价格计算、余额扣除和缓存变更必须处于同一服务器线程的受控事务中；SIMULATE 不得写状态，EXECUTE 必须重新读 EMC 余额。

缓存必须持久化并在玩家登出、重启后保留。否则玩家支付整桶 EMC 后只取出部分流体，剩余已付费流体会丢失。缓存不能按网络或适配器分别保存。目录显示量应为“缓存毫升数 + 可由未预留 EMC 兑换的毫升数”，但不能为了显示而预扣 EMC。

实现前要选定持久化位置。建议使用模组自己的世界级 SavedData，以 UUID 为玩家键；数据保存包含流体键、已预付毫升数和必要的格式版本。加载时校验流体注册表 ID，缺失流体的数据应安全隔离并记录诊断日志。若 ProjectE 账户与 SavedData 分别落盘，崩溃窗口可能让扣款和缓存保存不同步，必须设计恢复策略；最稳妥的方案是让 EMC 预留记录也写入同一缓存账本，或将“预扣 EMC + 缓存增加”做到可恢复的幂等事务。

## 平台接入

### 公共层

- 新增流体目录快照和玩家级缓存服务，不让公共核心依赖 AE2 或 RS 类。
- 按玩家 Knowledge 和桶映射发现流体，监听知识变化并使 AE2/RS 的流体视图刷新。
- 对显示容量使用 `long`，对 Forge `FluidStack`、RS API 等 `int` 容量边界做分段和饱和转换，避免溢出。
- 提供统一的查询、模拟排出和执行排出接口；适配层不能自行改写 EMC 或缓存。

### AE2

在 AE2 可选模块中增加流体存储适配，使 ME 终端能列出流体并能以 AE 的流体键进行模拟/执行提取。当前 AE2 `StorageCell` 接口使用通用 `AEKey`，因此沿用现有 EMC Cell 和所有者绑定，同时支持 `AEItemKey` 与 `AEFluidKey`。物品存储行为不依赖流体类加载。

### Refined Storage

RS 可选模块为 EMC 接口增加 `StorageType.FLUID` 外部存储提供者，与现有物品外部存储共用接口所有者和平台无关 Fluid Core。RS 外部存储节点一次配置为一种存储类型；若要同时浏览物品和流体，需要将物品型与流体型外部存储分别连接到 EMC 接口的不同侧。接口方向、网络生命周期刷新和 RS 过滤/优先级行为沿用现有实现；流体提供者单独处理 FluidStack 请求及模拟/执行。

## 配置建议

首版可加以下配置，避免把刷新策略和流体交易规则混在一起：

```toml
[fluid]
enabled = true
```

桶缓存单位固定为 1000mB，不建议配置化。现有显示刷新总时长和间隔设置继续用于物品与流体目录，`maxDisplayAmount` 可沿用为显示数量上限，但需明确其单位是各自的原生单位（物品数或 mB）。

## 验收清单

1. 仅 ProjectE + AE2、仅 ProjectE + RS、两者同时安装均可启动；缺少任一可选依赖时无类加载错误。
2. 学会装液桶后，终端在刷新周期内出现对应流体；遗忘桶知识后流体目录同步移除，已有缓存的处理规则符合确认后的产品选择。
3. 测试 1、999、1000、1001mB 以及跨桶的大请求；拆分请求与一次请求总 EMC 扣费一致。
4. SIMULATE 不扣款、不改缓存；余额不足时只排出可支付量；零 EMC、零价值桶和不存在的流体得到安全结果。
5. 测试缓存中的剩余流体可在 AE2/RS 入口间共享，不能重复提取；保存并重新进入世界后余额和缓存守恒。
6. AE2 流体终端及 RS 流体网格均能浏览、提取，并连接常见流体机器/管道完成使用。
7. 测试同一 tick 内竞争请求、网络重建、区块卸载、玩家登出、存档重启和流体标签差异。

## 已确认的产品选择

本次实现采用以下已确认约定：

1. **发现规则**：只显示玩家已学会且有正 EMC 价格的装液桶所代表的流体；无桶流体暂不支持。同一种流体存在多个已学会的桶物品时，按其中最低的正 EMC 价值定价。
2. **价格规则**：1000mB 按装液桶的完整 ProjectE EMC 价值收费，不扣空桶价值。
3. **缓存/遗忘规则**：整桶 EMC 预扣，缓存是玩家已付费的流体库存；遗忘桶知识后，缓存里的已付费流体仍可取完，但不再补充新缓存。

AE2、RS 适配和通用缓存核心已完成；AE2/RS 游戏内验收仍待完成。
