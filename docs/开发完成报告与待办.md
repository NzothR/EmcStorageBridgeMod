# 开发完成报告与待办

更新日期：2026-09-30

## 当前完成情况

### 公共 EMC 核心

- 使用 ProjectE 个人账户作为 EMC 和 Knowledge 的唯一数据源。
- 支持 EMC 物品存入、自动学习、提取、部分提取和模拟请求。
- NBT 开关控制是否接受带标签的输入；允许时按原始物品栈的 ProjectE 卖出值计入 EMC，存入时使用 ProjectE 持久 NBT 规则学习，显示和提取则使用 Knowledge 中的精确物品键。
- 显示数量默认封顶为 `2,147,483,647`，真实事务使用 `long` 与 `BigInteger` EMC 余额安全计算。
- 通过缓存和分批刷新维护网络终端中的显示库存。
- ProjectE 开启全知识后，将当前 EMC 映射物品展开成显式 Knowledge，同步玩家数据，使终端能够显示完整映射并允许在转化桌逐项遗忘。

### AE2

- AE2 为可选依赖；安装后注册 EMC 存储元件，不安装时不加载 AE2 集成。
- 元件可以绑定玩家、放入 ME 驱动器，并切换 NBT 策略。
- AE2 网络支持查看、存入、提取及基本自动合成请求。
- 同一个 AE2 网络内，同一玩家只启用一个 EMC 入口。
- 用户已验证元件放入驱动器、绑定、NBT 切换、学习、提取和基本合成下单。
- 1.1.0 增加流体键支持；AE2 的通用 EMC 元件可同时显示物品和流体，流体只允许提取。

### Refined Storage

- RS 为可选依赖；安装后注册 EMC 接口方块，不安装时不加载 RS 集成。
- 接口放置后绑定玩家；持贤者之石右键可切换 NBT 策略。
- 通过 RS 外部存储接入网络，并遵守外部存储过滤器、优先级和访问模式。
- 接口支持地图加载后的节点刷新；替换后的外部存储实例会从重复入口注册中清理。
- 用户已验证终端能查看 EMC 物品、学习新物品、存入及提取。
- RS 流体外部存储已按用户要求暂缓；当前接口只注册物品存储。

### EMC 流体

- 1.1.1 修正 AE2 流体键的标签身份：无标签保持为 `null`，与显式空标签区分，避免同名流体被 AE2 识别为不同库存键，导致自动合成模拟提取失败。
- 缓存数据升级到 v2；读取 1.1.0 缓存时将旧格式的空标签迁移为无标签键。
- 学会有正 EMC 价值的装液桶后，终端显示对应流体；同一流体存在多个已学会桶时按最低正 EMC 价值定价，每 1000mB 收取一个桶的 EMC 价值。
- 流体从 EMC 按整桶预付并缓存在世界 SavedData；AE2 适配层按请求量分次排出。
- 遗忘桶知识后，已付费缓存仍可显示和取出；没有可用缓存时不能继续兑换该流体。
- 首版仅支持有桶表示的流体，且不支持将流体存入 EMC 空间；`fluid.enabled` 可整体关闭流体视图与提取。

## 本次代码审查与调整

- 修复 NBT 显示与转换桌不一致的问题：移除对所有 NBT 条目的统一过滤，存入学习使用 ProjectE `getPersistentInfo`，显示与提取按 Knowledge 中精确 `ItemInfo` 键和对应 EMC 值处理；输入 EMC 仍从原始 ItemStack 计算。
- 公共事务类此前在方法签名中引用 AE2 的 `AEKey`，会给 AE2 软依赖带来类加载风险。现在改为只接收 Minecraft `ItemStack`，AE2 类型留在 AE2 适配层。
- 删除未被代码使用的 RS Integration workaround 配置项，避免提供无效开关。
- 显示刷新从固定的“每 tick 处理多少物品”改为按完整刷新轮次和刷新间隔计算批次。
- 调试生命周期日志与高频事务日志默认关闭，需要排查时可在配置中开启。
- 存储元件和接口模型已接入新像素贴图。

刷新批量的计算方式：

```text
每轮刷新次数 = ceil(refreshRoundTicks / (refreshIntervalTicks + 1))
每次处理物品数 = ceil(当前已学习物品数 / 每轮刷新次数)
```

刷新间隔为 `0` 时每 tick 刷新一次。若刷新间隔大于刷新轮次，批次会在一次刷新中处理完整列表；后续刷新仍遵循配置的间隔。

## 待办

### 优先处理

1. **AE2 流体合成回归**：验证自动合成能从 EMC FluidKey 提取对应流体，不再需要手工往另一个同名条目补桶。之后验收 1/999/1000/1001mB 提取、知识遗忘后缓存和存档重启持久性。详细用例见[流体兼容技术方案](1.1-流体兼容技术方案.md)。
2. **完整运行矩阵**：分别在仅 ProjectE + AE2、仅 ProjectE + RS、两者同时安装时启动游戏，确认可选依赖不会触发缺类错误。
3. **存储元件配方**：当前 RS 接口有合成配方；AE2 EMC 存储元件暂未配置生存模式配方，目前可从创造模式物品栏取得。
4. **大量 Knowledge 验证**：用大型整合包或全知识账户测试 1k、5k、10k 物品下终端刷新、MSPT、同步包大小和玩家存档增长。
5. **版本兼容矩阵**：核对 AE2/RS 声明的版本范围与实际 API。全知识展开目前调用 ProjectE 的 `EMCMappingHandler`，需重点验证目标 ProjectE 版本及后续版本。

### 延后处理

1. **RS Shift 连续取物显示归零**：按用户要求暂缓；当前用户认为可能是 RS 终端行为，待后续重新确认。
2. **合成与压力测试**：AE2 已完成基本下单测试，尚未完成大量并发提取、超大请求、跨网络竞争和性能基准；RS 自动化链也需要完整回归。
3. **运行时日志整理**：当前保留针对生命周期、缓存刷新和提取路径的诊断日志。发布前应再评估日志等级、采样和默认开关。

## 建议的后续验收顺序

1. 用 ProjectE 的全知识道具解锁全部 EMC 物品，确认 AE2 与 RS 终端在一轮刷新内逐步出现物品。
2. 在转化桌分别遗忘普通 EMC 物品与带 NBT 物品，确认 Knowledge 与网络显示同步。
3. 分别运行 AE2-only 和 RS-only 环境，确认物品注册、启动、进图和交易正常。
4. 在 RS/AE2 各自网络执行自动化下单、连续批量提取与超大请求。
5. 开启 `debug.enableDebugLog` 与 `debug.logTransactions`，记录大型 Knowledge 刷新耗时和服务器 MSPT。
